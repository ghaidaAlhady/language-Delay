# Claude Code Master Prompt — Smart Guide for Children's Language Delay

You are the lead software architect and senior full-stack engineer responsible for building a production-quality MVP named **Smart Guide for Children's Language Delay**.

Work directly inside this repository. First inspect every existing file, especially `PROJECT_SPEC.md`, `CLAUDE.md`, the five knowledge-base workbooks in `knowledge_base/`, and the datasets in `dataset/`. Treat `PROJECT_SPEC.md` as the authoritative product scope. Do not silently change approved decisions.

## Operating method

1. Start by auditing the repository and writing a concise implementation plan in `docs/IMPLEMENTATION_PLAN.md`.
2. Identify assumptions, risks, missing data, and contradictions in `docs/DECISIONS_AND_ASSUMPTIONS.md`.
3. Build incrementally in small, reviewable commits or logical change groups.
4. After each major phase, run tests, formatters, linters, and builds. Fix failures before continuing.
5. Never leave mock data, placeholder screens, fake AI responses, hard-coded reports, or disconnected buttons in the final implementation.
6. Preserve Arabic RTL support and English localization from the beginning.
7. Do not implement features listed as out of scope for version 1.
8. Do not claim medical diagnosis. The application must clearly state that it is a supportive screening and guidance tool, not a substitute for a speech-language pathologist, medical diagnosis, or treatment.
9. Use secure defaults. Never commit secrets, API keys, personal child data, generated reports, local databases, or environment files.
10. When requirements are ambiguous, choose the safest, simplest decision consistent with the approved specification, document it, and continue without repeatedly asking for confirmation.

## Approved technology stack

- Mobile: Flutter, Dart, Material 3
- State management: Riverpod
- Navigation: GoRouter
- Localization: Arabic and English; Arabic is default; full RTL support
- Backend: Python 3.13, FastAPI, Pydantic v2, SQLAlchemy 2.x
- Database: SQLite for MVP, with repository abstractions that allow later migration
- Authentication: email/password and Google Sign-In

## Product scope

The application supports one user role only: **Parent**. A parent may create multiple child profiles. Each child has isolated assessments, reports, the latest weekly plan, activity completion records, follow-ups, and chatbot conversations.

Child profile fields:
- name
- date of birth
- computed age
- gender
- home language
- previous diagnosis status/details
- hearing problems
- hearing-aid usage
- notes

Assessment flow:
- Show an introduction explaining purpose, duration, accuracy expectations, and non-diagnostic disclaimer.
- Display one question per screen.
- Include progress indicator, Next, and Previous.
- Allowed responses: Always, Often, Sometimes, Rarely, Never.
- Select questions according to the child's age and retrieved knowledge-base records.
- Do not train a custom machine-learning model.

Assessment analysis must produce structured, evidence-grounded output:
- case summary
- strengths
- skills requiring support
- percentage per language domain
- priority ranking
- confidence score
- recommendations
- referral guidance when strong concern indicators exist

Reports must contain:
- child basics
- assessment summary
- level per domain
- strengths
- weaknesses / support needs
- one main weekly goal
- recommendations
- confidence score
- disclaimer
- downloadable PDF

Weekly plan:
- exactly 7 days
- exactly 2 activities per day
- each activity includes name, objective, rationale, tools, steps, duration, and difficulty
- parent can mark an activity completed
- system calculates adherence percentage
- retain only the latest weekly plan, while preserving assessments, reports, follow-up history, and chat history

Weekly follow-up:
- parent answers follow-up questions after the week
- AI analyzes progress
- a new weekly plan replaces the previous active plan
- prior plan data must be handled according to the approved retention rule: keep historical assessment/report/follow-up evidence, but only one active/latest weekly plan

Specialized chatbot:
- answer only questions about child language delay, the child's report, weekly plan, and recommended activities
- use RAG before generating an answer
- refuse unrelated requests politely
- explain reports and activities
- suggest alternative activities
- escalate to professional consultation when safety or strong delay indicators require it

Knowledge bases:
- KB01: age-based language milestones
- KB02: home activities
- KB03: decision rules
- KB04: report templates
- KB05: assessment questions

## Data and security rules

- Hash passwords securely using a modern password hashing library.
- Validate Google identity tokens server-side.
- Use short-lived access tokens and a safe refresh-token strategy suitable for a mobile client.
- Enforce ownership checks for every child-specific endpoint.
- Never expose data belonging to another parent.
- Validate all input and output schemas.
- Rate-limit authentication and AI endpoints.
- Add secure CORS configuration by environment.
- Do not log passwords, tokens, health-related free text, full chatbot messages, or generated child reports.
- Add privacy policy and terms screens.
- Provide account deletion and child deletion endpoints with cascading data deletion.
- Add consent acknowledgment before the first assessment.
- Store timestamps in UTC.

## RAG and AI requirements

- Load and normalize the supplied Excel/JSON knowledge base.
- Validate required sheets, columns, identifiers, age ranges, and references.
- Build deterministic retrieval with metadata filters, especially age and knowledge-base type.
- Keep retrieval and generation separate.
- Require the LLM to return strict JSON matching Pydantic schemas.
- Reject and retry malformed outputs with bounded retries.
- Include retrieved source IDs in internal analysis records and report-generation inputs.
- Never fabricate medical claims or references.
- Add deterministic fallback behavior when the AI API is unavailable.
- Prevent prompt injection from user chat text and knowledge-base content.
- The chatbot must include a domain classifier/guard before generation.

## Acceptance criteria

The MVP is complete only when a new user can:
1. register or sign in with Google;
2. add more than one child;
3. start an age-appropriate assessment and move backward/forward without losing answers;
4. submit the assessment and receive a validated AI/RAG-generated report;
5. download a readable Arabic or English PDF;
6. view a 7-day plan with two activities per day;
7. mark activities completed and see adherence;
8. complete weekly follow-up and receive a replacement current plan;
9. use the specialized chatbot for in-scope questions and receive a refusal for out-of-scope questions;
10. access historical assessments and reports while seeing only the latest weekly plan;
11. delete a child or account and remove associated records;
12. use the application in Arabic RTL and English LTR;
13. encounter useful validation and recovery messages rather than crashes or fake success states.
